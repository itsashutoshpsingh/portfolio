Work

Three benchmarks, one question

How often does the evidence pipeline quietly get it wrong? Each project answers with a number, a method you can rerun, and a list of what the number does not prove.

An investigation is only as sound as the error rate behind it. I measure that rate, then publish the misses.

How every project works

01

Start from ground truth

Exchange proof of reserves lists, a script that logs its own actions in UTC, a receipts root in a block header. Known answers come first, tools come second.

02

Test differentially

Run several rules, providers or tools on the same evidence. Compare them with each other and with the truth, then classify every mismatch instead of counting it blindly.

03

Publish the error profile

Pinned versions, one command to reproduce, aggregate results only, and a written list of what went wrong. Hiring managers and courts should be able to check the work.

Questions reviewers ask

Is the data real?

Yes. Ethereum and Base data come from public mainnet nodes over fixed, finalised block windows. Forensic results come from real disk images built and timed by script. No number on this page is estimated or typed in by hand; each is read from the repository's results file.

Are you measuring Chainalysis, Elliptic or TRM?

No. The clustering benchmark tests open, published heuristics from the research literature. Commercial products use their own rules and data, and nothing here should be read as a claim about them.

Why publish aggregates only?

A clustering error can wrongly connect a real person to a crime. The repositories publish counts and rates, never a claim that a specific address belongs to someone.

Can I reproduce a result?

Each repository pins its tool versions and has one command that reruns the pipeline. Disk images and raw chain data are too large for git, so the repositories publish hashes and build steps instead.

Is every mismatch a bug?

No, and most are not. Two tools can both be right and still disagree because they report different things. Each mismatch is classified as a tool bug, documented behaviour or my own mistake, after reading the tool's documentation.

Why does this matter for compliance and courts?

Cluster attributions and timelines are used as evidence, often with no stated error rate. The UK Forensic Science Regulator's Code expects methods to be validated, and these benchmarks are a template for that validation evidence.
